# Build & release

TrueFeel (`com.truefeel` on iOS, `com.truemate.girlfriend` on Android).
Expo SDK 54 / React Native 0.81, managed workflow — there is no committed
`ios/` or `android/`, both are generated by `expo prebuild`.

---

## Quick reference

```bash
yarn install                      # never `npm install` — the lockfile is yarn's
npx expo start --dev-client       # Metro for a dev build
npx expo run:ios                  # local iOS build onto a simulator
npx eas build --platform android --profile production   # release AAB
```

---

## Before you build anything

**Use `npx expo install`, never `yarn add`, for any `expo-*` or React Native
package.** `yarn add` resolves to `latest`, which will not match the SDK. This
has already cost one Play rejection: `expo-localization` drifted to 57.x
against an SDK 54 app, the native module threw `NoSuchMethodError` on launch,
and 35% of sessions crashed before anything rendered.

Check for drift at any time:

```bash
npx expo install --check     # lists packages that disagree with the SDK
npx expo install --fix       # pulls them back in line
```

`react-native-google-mobile-ads` is pinned **exactly** (`16.3.4`, no caret) on
purpose. 16.4.0 pulls `play-services-ads` 25.4.0, which carries Kotlin metadata
2.3.0; SDK 54 compiles with Kotlin 2.1.0 and reads at most one minor ahead, so
the build dies in `:react-native-google-mobile-ads:compileReleaseKotlin`. Do not
loosen that pin without checking the ads SDK's Kotlin metadata version.

## EAS build

| Profile | Output | Notes |
| --- | --- | --- |
| `development` | APK, dev client | needs Metro running to load JS |
| `preview` | AAB, internal | for Play internal testing |
| `apk` | APK | extends `preview`; installable directly, best for hand testing |
| `production` | AAB | `credentialsSource: "local"` — see below |

```bash
npx eas whoami                    # must be hoangcuongdcyb365
npx eas build --platform android --profile production --non-interactive
```

The EAS project is `@hoangcuongdcyb365/truemate`
(`956f5391-596e-4873-8dc2-331df23f5cd3`), set in `app.config.ts`. An older
project `67c3b1c6…` exists under a different account; builds cut before
2026-08-28 point their OTA there, so pushing an update for those users needs

`versionCode` is generated from the clock (`app.config.ts`, minutes since
epoch), so every build is higher than the last with nothing to bump by hand.

### The production profile needs a keystore on disk

`production` signs locally, so `credentials.json` and `upload-keystore.jks`
must be in the repo root. Both are gitignored, so a fresh clone has neither and
the build fails at the credentials step with
`credentials.json does not exist in the project root directory`.

Copy them from the backup — see `docs/CREDENTIALS.md`.

This is the only key Play accepts for `com.truemate.girlfriend`. Signing with
anything else means the upload is rejected and the listing can never be updated
again.

## iOS

```bash
npx expo prebuild -p ios --skip-dependency-update react-native,react
cd ios && pod install && cd ..
npx expo run:ios --device "<simulator udid>"
```

`keytool` is unavailable without a JRE, which is worth knowing if you ever need
to verify a keystore: parse the JKS directly instead (cert SHA-256 from the
first chain entry; the trailing 20 bytes are a SHA-1 of the store password plus
the literal `Mighty Aphrodite` plus the file body).

## Gotchas that will waste your afternoon

**Metro port 8081 is often taken** by the yuuki RN project's dev server. `expo
start` then refuses non-interactively and the app silently connects to *yuuki's*
bundle, failing with `Property 'MessageQueue' doesn't exist`. That error means
wrong bundle, not broken code. Use `--port 8082`, or stop the other server.

**expo-doctor is disabled in CI.** All four profiles set
`EAS_BUILD_DISABLE_EXPO_DOCTOR_STEP: "1"` in `eas.json`. That is the check that
would have caught the `expo-localization` mismatch above. Consider re-enabling
it; until then run `npx expo install --check` yourself before a release build.

**`USE_TEST_ADS`** (`src/config/ads.ts`) is `__DEV__`: dev builds serve Google's
sample creatives, release builds serve real ones. Never tap an ad on a release
build of your own app — AdMob counts that as invalid traffic and bans accounts
for it. To exercise placements by hand, use a debug build or register the device
as a test device in the AdMob console.

**Cold start holds for ~2.8s minimum** (`SPLASH_MIN_MS` in
`src/navigation/AppNavigator.tsx`). That dwell exists so the splash banner has a
window to fill; without it the boot screen resolves off local storage in well
under a second and the ad never arrives. It is the one number to turn if boot
feels slow.

## After uploading to Play

Do not roll out to 100% straight away. Push to internal testing or a staged
rollout, then watch **Play Console → Quality → Android vitals → Crashes and
ANRs** for a few hours. That is the only crash reporting this app has —
Crashlytics is not installed, so a crash is invisible until Google surfaces it
or a review fails.

The launch crash that got the app rejected showed up there as
`expo.modules.localization.LocalizationModule.definition /
java.lang.NoSuchMethodError`.
